Abstract

Remote scene visualization enables users to view remote scenes from a local site. Conventional remote visualization systems rely on video or point-cloud streaming and experience high latency and bandwidth consumption, especially in network-constrained environments. To mitigate this problem, we propose a scene-graph streaming framework for efficient, incremental remote 3D scene visualization. On the remote side, visual observations are converted into a structured 3D scene graph represented in JSON format using 3D scene understanding techniques. The compact scene graph is then transmitted over the communication network to the local side, where it enables incrementally generating and updating the 3D model of the remote environment. By transmitting compact, JSON-based 3D scene graphs instead of dense visual data, the proposed framework reduces communication requirements while preserving the information needed for 3D scene generation. Experimental results show that for structured indoor environments, the proposed approach achieves a 24.12 ms end-to-end latency reduction and a 97.5% reduction in bandwidth consumption compared with the traditional image-based approach in good internet conditions.

Motivation

TeleScene in one picture. Conventional remote visualization streams dense video, which costs a lot of bandwidth and adds communication latency. TeleScene streams a lightweight JSON 3D scene graph instead, and the local side regenerates the 3D scene from it.

Method Overview

System overview. On the remote side, RGB-D observations and camera poses are encoded into lightweight 3D scene graphs. Only the changed part of the graph is streamed as JSON over Fast DDS. On the local side, an immersive 3D scene is generated and updated incrementally from the streamed graph.

Qualitative Results

Scenes from unseen rooms in the test set. The remote side only sees partial point clouds. The local side retrieves complete assets and infers plausible poses, even for objects that were barely observed (blue boxes).

TeleScene Dataset

There was no public dataset for this task, so we built one in AI Habitat (ReplicaCAD) for training both the remote-side GNN and the local-side generator. Validation and test sequences come from rooms that are never seen in training.
